# 为什么技能是数据，而不是代码

> 这份文档解释 `livingworld-dsl` 的三个核心判断。它不是 API 文档——代码注释比文档更详细；它回答的是"为什么长这样"。

---

## 一、技能写成类，三个月后会死

传统写法，一个技能一个类：

```csharp
public class Backstep : ISkill
{
    public override void Execute(Unit caster, Unit target) { /* ... */ }
}
```

十个技能没问题，五十个开始难受，两百个就是灾难：每次平衡性调整都要动代码、发版、走审核；策划看不到技能长什么样，只能问程序；任何一个改动都可能碰到别的技能的公用逻辑。

改成数据之后，同一件事变成：

```
技能（什么时候放、花什么） → 效果列表 → 原子方法（真正做事）
```

三层各自独立变化：

- 想加一个新招式？写两个 JSON。
- 想调数值？改 `$expr` 里的系数，不碰代码。
- 想加一种新的"做事方式"（比如"给目标挂一个持续掉血的标记"）？这时候才需要写代码——写一个 `MethodSpec`，全体技能立刻都能用它。

**变化频率决定了抽象层级。** 招式组合变化最快，所以是数据；原子行为变化最慢，所以是代码。把两者放对位置，才谈得上"内容生产"。

---

## 二、能在启动时炸的错，不要留到运行时

这是 `MethodRegistry` 存在的主要理由。注册期会拒绝四类写法：

| 错法 | 为什么必须启动即拒 |
|---|---|
| Id 不是 `<域>.<动作>` | Id 是契约。数据里一旦引用，改名就要迁移。格式约束是最便宜的护栏 |
| 参数重名 | 按位置绑定 + 按名传参两种调用方都会静默拿错值 |
| 必填参数跟在可选参数后面 | 语法合法，但按位置绑定永远传不进去——只会在运行时稳定返回错误码 |
| 能力位声明了多个 | "需要 A 或 B" 和 "需要 A 且 B" 语义不同，不拆开就永远说不清楚 |

第三条值得展开，因为它是真实踩出来的：

```csharp
// 声明上完全合法，编译通过，测试也不报错
new ParamSpec { Name = "amount",  IsRequired = true  }
new ParamSpec { Name = "modifier", IsRequired = false }
new ParamSpec { Name = "type",    IsRequired = true  }   // ← 永远传不进来
```

调用方按位置传参时，第三个参数会被当成 `modifier`，而 `type` 永远缺省。表现形式不是崩溃，是"这个技能偶尔打不出伤害"，排查成本极高。

**判断标准**：一个错误如果"语法合法、语义必错"，且诊断它需要跨三四个文件，就值得让程序在启动时死给你看。

## 三、一张方法表，两个消费者

方法表除了给运行时用，还给大模型用——它会变成工具描述，塞进提示词。

```csharp
IReadOnlyList<MethodSpec> GetInvocableBy(ExecutionPrincipal principal)
    => _methods.Values
        .Where(principal.CanInvoke)
        .OrderBy(m => m.Id, StringComparer.Ordinal)
        .ToArray();
```

两个细节：

**排序是刻意的。** 工具表顺序变化会让提示词缓存失效（成本上升），也会让回归测试的 diff 变得不可读。用序数排序，保证同一份代码永远产出同一个顺序。

**按身份过滤，不是按场景过滤。** 一个樵夫不该看见 `unit.apply_damage` 以外的世界；一个访客不该看见"夺舍"。过滤依据是调用者身份，不是"当前在哪个界面"——后者会随着 UI 改动漂移。

## 四、表达式必须是沙箱

`$expr` 支持四则运算、比较、取字段，**不支持**：方法调用、循环、赋值、闭包。

理由不是安全（虽然顺带解决了），而是**可回放**：

> 同一个效果，在服务器和客户端、在第一次和第三百次执行时，必须算出同一个数。

一旦允许任意方法调用，就允许了 `DateTime.Now`、`Random`、外部 IO。存档对账会在某一天突然开始失败，而失败点离真凶隔着几万行。

所以随机数走注入的种子化服务，时间由世界时钟统一供给，表达式内核只做纯计算。

---

## 五、代价

诚实地列出这套设计的成本：

- **表达力有上限。** 复杂逻辑（多段位移、条件分支链、跨单位协同）写不出优雅的数据，只能退回代码。这是刻意的：数据能表达一切时，你就得到了一个没有调试器、没有类型检查的编程语言。
- **需要工具。** 没有校验器和错误定位，写 JSON 的人会在第 2 小时开始骂人。所以每条错误都带 `Source` + `Pointer`（JSON Pointer）+ 修复建议。
- **热加载需要设计。** 数据可变意味着运行中的世界可能一半旧一半新。我们的做法是版本号 + 迁移链，高版本数据直接拒，不猜。

---

## 六、一句话

**让变化最快的东西变成数据，让变化最慢的东西变成代码，并让所有错误在你能看见的地方爆炸。**
